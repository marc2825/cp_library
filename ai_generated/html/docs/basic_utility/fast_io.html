共通FastIO

先行include・型別名・グローバルなscanner/printerに依存しない、FILE*ベースの共通入出力です。整数をバッファから直接読み書きし、EOFとエラーを区別します。

使用例 #

#include <cstdio>
#include <stdexcept>
#include "basic_utility/fast_io.hpp"
int main() {
    std::FILE* file = std::tmpfile();
    if (!file) throw std::runtime_error("tmpfile failed");
    {
        cp::FastPrinter writer(file);
        writer.writeln(-42, "hello", 1.25);
        writer.flush();
    }
    std::rewind(file);
    {
        cp::FastScanner reader(file);
        __int128_t number; std::string word; double real;
        if (reader.read(number, word, real)) {
            cp::FastPrinter out;
            out.writeln(number, word);
            out.write_fixed(real, 2); out.writeln(); out.flush();
        }
    }
    std::fclose(file);
}

出力:

-42 hello
1.25

APIと使用条件 #

FastScanner・FastPrinterは各64KiBのバッファを持ちます。BasicFastScanner<N>・BasicFastPrinter<N>で正の容量Nを指定できます。既定のFILEはそれぞれstdin/stdout。**FILEを所有せず、closeしません。FILE*はオブジェクトより長く生存させます。** コピー・ムーブは不可。nullはinvalid_argumentです。

API 意味
read(T&) -> bool トークンを1つ読む。EOFならfalse、対象値は保持
read(a,b,...) -> bool 左から順に読む。途中でEOFならfalse、それ以前に読めた値は更新済み
write(value) 1値を出力。charは1文字、文字列はそのまま
write(a,b,...) / writeln(a,b,...) 空白区切り。後者のみ末尾改行。引数なしのwritelnは改行のみ
write_fixed(long double x,int digits=10) 小数点以下digits桁、0〜1000。それ以外はinvalid_argument
flush() / failed() 内部バッファとstdioをflush／出力失敗状態を取得

整数はbool・charを除く組み込み整数（128bit含む）。boolの出力はstd::coutと同じく1／0です（読み取りは非対応）。charは空白を飛ばして1バイトだけ読みます。符号付き／なしcharを数値で使う場合はsigned/unsigned charを指定します。整数トークンは[+-]?[0-9]+、unsignedへの-は-0を含め拒否。極小値・極大値を読み書きできます。構文不正はinvalid_argument、範囲外はout_of_range。エラーのトークンは末尾まで消費し、対象値は保持するため次のトークンを読めます。

空白はバイト値0〜32。stringは次のトークンで置換し、長さに固定上限はありません。float/double/long doubleはstrtof/strtod/strtoldで読み、ERANGE（処理系が報告するunderflowを含む）やNaN・無限大をout_of_rangeとして拒否。通常出力は型のmax_digits10桁、固定出力はsnprintfを使用します。Cロケールの影響を受けるため、競技入力では既定のCロケールを使ってください。浮動小数点の丸めは処理系の規約に従います。

I/Oエラーはios_base::failure。出力エラー後はfailed状態になり、以降の書き込み・flushも例外です。デストラクタはflushを試みますが例外を外へ出さないため、エラーを確認する場合やインタラクティブ問題では明示的にflushしてください。FILE*を共有する別のreaderやiostreamとの読み取り混在は、先読みしたバッファがあるため避けます。

入力はLinux（glibc）・macOSではread(2)でバッファを埋めます。届いた分だけで読み進めるので、インタラクティブ問題でも次の入力を待ち続けません（質問を出力してflush()し、応答を読む流れで使えます）。次の場合はfreadで読みます。

  • 構築時点でFILE*に未読のデータが残っている（先にscanfや同期モードのcinで読んだ）。stdioが先読みした分を失わないためです
  • fmemopenなどファイル記述子を持たないFILE*、またはそれ以外の環境

freadはバッファが埋まるかEOFまで戻らないため、この場合はインタラクティブ問題に使えません。インタラクティブ問題では、最初からFastScannerだけで読んでください。

整数・文字列の読み書きは処理バイト数Lに対しO(L)時間。固定バッファO(N)、string入力はO(L)、浮動小数点はトークン／整形文字列分の追加領域を使います。modintはval()を出力し、入力は整数を読んで構築するかiostreamの>>を使います。

旧入口からの移行 #

旧 fast_io_yosupo.hpp・fast_io_nyaan.hpp はリポジトリ直下の depricated/ に保存しています。新規コードはこのヘッダと明示的なcp::FastScanner in; cp::FastPrinter out;を使ってください。scanner.readは戻り値boolを確認し、printer.writelnはout.writelnへ移します。旧APIのバッファ・公開フィールド・read_unsafe・closeなどの互換を新型に仮定しません。

使用する問題と検証 #

Library Checker A + Bのローカル入出力を検証します。1バイトのバッファ、末尾改行なし、20万バイトの空白／トークン、整数極値、浮動小数点往復、不正トークン、EOF、読み書きエラーを確認します。

python3 verify/run_foundation.py / --sanitize（make verify-foundation）で単独・重複include、全カテゴリとの混在、複数翻訳単位、Debug/Release、使用例、独立した比較を検証します。オンライン提出・ACは未確認です。検証範囲。
