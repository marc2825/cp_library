3.11 木アルゴリズム

木・森のアルゴリズムを tree/ にまとめます。共有の Graph を使い、C++17・namespace cp・0始まり・半開区間が基本です。必要なヘッダだけ、または tree/all.hpp を include します。

共通条件と選び方 #

Graph を受け取る API は無向の木・森を入力とし、有向・自己ループ・多重辺・閉路をinvalid_argumentで拒否します。根付きの処理は指定した根の成分を先に、それ以外は最小番号の頂点を根にします。距離の算術条件は RootedTree に記載。連結な木を要求するのは tree_diameter・tree_center・weighted_tree_center・unrooted_tree_hash・tree_isomorphism・prufer_encode、非負の重みを要求するのは tree_diameter（assert）・weighted_tree_center・DynamicTreeDiameter（invalid_argument）です。prufer_encode と prufer_decode(0,…) は空を拒否します。LinkCutTree・EulerTourTree・Dynamic/Lazy Top Tree・MergeTree は Graph を受け取らず、頂点数を指定して構築します。

BinaryLifting は Graph を使わず遷移先の配列を受け取り、閉路・自己ループを許容します。-1 は終端です。LCA が必要なら DoublingLCA、祖先や任意の遷移の反復だけなら BinaryLifting を選びます。

木DPのコールバックは merge(S,S)->S、add_vertex(S,v)->R、lift(R,送信元→受信先の辺)->S。S と R は別の型にできます。全方位木DPでは結合則と単位元が必要です。親側も含めて隣接順を保つので、非可換の演算にも対応します。状態の演算が重い場合はその費用を計算量に掛けます。

部分木クエリでは preorder 上の [tin,tout) を Fenwick や Segtree へ渡します。RMQ の LCA を実装したい場合は EulerTour.walk と Sparse Table を組み合わせられます。

検証 #

python3 verify/run_tree.py
python3 verify/run_tree.py --sanitize
python3 verify/run_graph_tree.py --sanitize --stress
node verify/visualizations/tree_model_test.js
node verify/visualizations/tree_browser_test.mjs --browser /path/to/chromium

--compiler clang++ 等でコンパイラを変更できます。C++17・警告エラー、tree/ の全ヘッダの単独 include（debug/release）、既存カテゴリ・旧APIとの混在、複数翻訳単位、基本7項目の使用例7本、7ジャッジ形式・336ケースを確認します。

単体検証は339個の非空な小さな森を全根で、300個のランダムな森／木を全頂点対で確認します。再帰DFS・BFSパス・全頂点部分集合・全根からのDPと比較し、文字列連結による非可換集約と辺の送受信方向も確認。終端を含む遷移表700個、uint64の境界、20万頂点のパス・星型・閉路を含みます。空・不正な木・距離超過も検査します。オンライン AC は未確認です。

図解は1720バッチ・34238スナップショットを独立オラクルと比較します。全方位DPの各有向メッセージ・prefix/suffix、部分木区間、往復列、全DP状態、巨大なkの閉路も検査します。ブラウザの操作・入力検査・再生・リンク・390px表示は別のブラウザ検証で確認します。
